# ADR 0060: Two front doors: AGENTS.md for users of the tool, CLAUDE.md for its developers

Status: accepted by the owner on 2026-11-13 (issue 603, decisions in issue 613). Built (issues 616 to 628, 633 to 639). Decision A-1 of the agent interface.

## Context
Most users of workbench will be other AI agents building and testing an app against it. Today they have to read the manual and the CLI help (thousands of lines) before they can do anything. CLAUDE.md already serves agents that change this repository, and it would be a poor first read for an agent that only wants a test target.

## Decision
- `AGENTS.md` at the repository root is for agents **using** workbench as a test target. It is at most 2,000 tokens (estimated as characters divided by 4; a test enforces it) and has these parts: what this is, three start commands, an endpoint table, the ten verbs that matter, the recipes, the rules, the MCP one-liner and the contract version.
- `CLAUDE.md` stays for agents **developing** workbench. Each file opens with one line pointing at the other.
- The endpoint table and the verb list are generated by `python -m benchctl.agents` between markers in `AGENTS.md`; `validate.sh` fails when they are stale, so the file cannot drift from the code.

## Consequences
- One more root file to keep short. The generated blocks make that cheap.
- The rules agents must follow (no sudo, never edit `compose/generated`, stop what you started, REFUSED is a decision) get one home they will actually read.
